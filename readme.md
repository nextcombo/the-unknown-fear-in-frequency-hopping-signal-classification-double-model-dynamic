# The "Unknown Fear" in Frequency Hopping Signal Classification? Double Model + Dynamic Threshold, Teach You to Build a Robust Recognition System! [Attached Python Code]

In the realm of frequency hopping signal classification, what is often referred to as "unknown fear"? A dual-model approach combined with dynamic thresholds teaches us how to build a highly robust recognition system! Introduction: In complex electromagnetic environments, traditional deep learning models function like students who answer questions blindly—even when faced with unfamiliar questions, they still try to guess an answer. Today, we will delve into how to leverage a dual-model architecture and a dynamic threshold mechanism based on a real FHSS (Frequency Hopping Spread Spectrum) signal classification prediction system, endowing AI with the ability to acknowledge its uncertainty. In the field of radio signal monitoring and countermeasures, classifying FHSS signals is a classic challenge. Due to the extremely complex electromagnetic environment, receivers not only face known types of signals (such as 32 predefined categories like AIR2s and T0001), but more frequently encounter unknown interference signals or new communication systems. Traditional convolutional neural networks (CNNs) perform classification by having the final layer typically be a Softmax, forcing the input to belong to one of the known categories. This introduces a fatal flaw: in the face of unknown signals, the model still makes high-confidence incorrect predictions. How can this problem be solved? This article will share a system architecture solution that combines high accuracy with strong generalization capabilities, from theoretical design to engineering implementation.
💡 Core Theory One: Break the "closed set" curse - Unknown category detection based on Softmax probability in machine learning theory, standard classification tasks are called closed set recognition, while introducing unknown categories is called open set recognition. Our system adopts an elegant and easy-to-implement solution: a rejection mechanism based on confidence thresholds.
🔬 Theoretical Deconstruction: When we feed a signal's time-frequency graph into the model, it outputs a Logits vector. After being transformed by the Softmax function, it becomes a probability distribution. In traditional logic, we directly take it as the prediction result. However, in open set environments, we introduce a dynamic threshold (Threshold):
If: The model is deemed "sufficiently certain," the predicted category is output.
If: Triggered by an unknown category rejection, the sample is marked as "Unknown".
🧠 Theoretical support: This is based on uncertainty estimation. When the model encounters samples that differ significantly from the distribution of training data (Out-of-Distribution, OOD), its output probability distribution tends to become flat, with a significant decrease in the highest probability value. Leveraging this characteristic, we can achieve unknown category detection without modifying complex network structures through post-processing. In system code, this logic is encapsulated very cleanly: if max_prob < threshold: return {'final_prediction': 'Unknown', 'is_unknown': True, ...}
Moreover, the system not only outputs "Unknown", but also the threshold gap: threshold_gap = threshold - max_prob. This metric will be useful in subsequent "Unknown Category Details": the larger the gap, the farther the signal deviates from the known distribution, possibly indicating a new signal type.
🚀 Core theory two: dimensionality reduction strike - CNN + Transformer hybrid architecture for FHSS signals' particularity (with time-dimensional frequency hopping characteristics). A single architecture often struggles to balance local texture features and global temporal hopping relationships. The system introduces a second model: ResTransformer.
🔬 Theoretical breakdown This is a very cutting-edge hybrid architecture idea in computer vision. Its core innovation lies in: not simply cutting the image into pieces, but slicing according to the signal's temporal sequence.
1  
Feature extraction base: still using ResNet18 to remove fully connected layers, serving as a powerful local feature extractor (CNN is good at extracting texture and edge features on the spectral graph).
2  
Serialization construction: divide the input time-frequency graph into seq_len (e.g., 8) patches along the width direction.
The design is very clever: the FHSS signal in the horizontal direction usually represents the time axis. By dividing it into 8 segments, it precisely corresponds to the frequency hopping states of the signal at different time slices.
Transformer encoding: The feature vectors of these 8 patches are fed into a Transformer. The self-attention mechanism of the Transformer can capture the dependencies between these 8 time slices—i.e., the "regularity of frequency jumps".
CLS token mechanism: Inspiration from ViT, a learnable classification token [CLS] is concatenated at the beginning of the sequence. After multiple layers of Transformer Encoder, [CLS] integrates global temporal jump information and is finally used for classification.
Inspiration point: Often, simply applying Vision Transformer is not effective because it overlooks prior knowledge specific to the domain. Combining "the physical meaning of images (time slice)" with "Transformer's global modeling capability" is key to advancing algorithm engineers. ResNet is responsible for "seeing each moment's frequency", while Transformer is responsible for "understanding the regularity of frequency jumps".
Core theory three: Strategic planning - dynamic thresholds and sensitivity analysis thresholds: What is the appropriate value? 0.5? 0.8? Or 0.9? This is the most troublesome issue in actual business operations. Our system does not set the thresholds rigidly but provides a complete set of threshold analysis and evaluation systems.
Theoretical breakdown: The system implements a function named compute_threshold_sensitivity that iterates through all possible thresholds from 0.1 to 0.95, calculating the number of samples labeled as "unknown" under each threshold. This essentially plots a threshold-unknown rate curve, which contains profound theories of precision-recall trade-off:
Threshold set low (e.g., 0.3): There is almost no unknown sample intercepted, and the accuracy of known categories appears very high, but the system tends to "miss" new interference signals, misclassifying them as known signals (high risk).
Threshold set high (e.g., 0.9): A large number of known samples are judged as unknown due to insufficient confidence, resulting in a high detection rate of unknowns, but the availability of known categories significantly decreases (conservative strategy). The system provides a "threshold sensitivity analysis chart" for business personnel to intuitively see the curve's turning points. Even better, it supports real-time recomputation without model participation (recompute_with_threshold).
💡 Inspiration Point: The delivery of algorithms is not the end. An excellent AI system must provide "explainable tuning knobs." Since the softmax probability is monotonically related, we only need to save all category probability distributions during inference. Subsequent adjustments to the threshold do not require rerunning the model inference; instead, simple logical judgment can update all statistical indicators and confusion matrices instantly at lightning speed. This "decoupling of computational power" concept is invaluable in edge computing scenarios.
🛠️ Core Theory Four: The Art of Engineering Deployment - Memory and Computing Stance
Even the best theories can be useless if an image inference results in OOM (Out of Memory) error. In terms of engineering implementation, this system demonstrates exceptional maturity.
🔬 Theory Dissection 1. The batch processing mechanism faces the challenge of handling up to 200 images at once without resorting to brute force with a for loop or blindly loading everything into the GPU. Instead, it sets BATCH_SIZE = 10.
Theoretical Basis: GPU memory is fixed, and the batch size has a linear relationship with memory usage. By dividing the work into small batches, we can control the peak memory usage at a safe level, and the time.sleep(0.1) between batches can also keep the GPU temperature stable, preventing frequency reduction.
Stateful session management: Web systems are usually stateless. However, prediction results (including image paths and probability distributions) are very large. The system uses Flask-Session's filesystem storage to persist session data to disk instead of allocating it to memory or Redis.
Advantages: The system retains the user's last 200 predictions of images after a service restart, greatly improving the interaction experience.
Temporary file lifecycle management: After predicting the images, they are saved in a temporary directory. The system will precisely delete files that have been over 24 hours old during startup and cleanup, preventing silently full disk space, which aligns with the system resource bottom-line strategy.
